このファイルはリポジトリの現行状態に追随して随時更新する一覧です。日付をファイル名に持たせると「ファイル名の日付と中身の時点がずれる」問題が起きるため、ファイル名は固定し、時点とバージョンは上の2行で管理します。特定日のスナップショットを残す運用はしていません。

配布ファイルの完全性を利用者が確認できるようにするための一覧です。パスはすべてリポジトリルートからの相対パスで記載しています。

Git管理対象予定は68ファイルです。このSHA-256一覧ファイル自身は自己参照を避けるため検証対象から除外し、残る67ファイルについてSHA-256を記録・検証しています。

1. 前提

対象に含まれないもの

以下は git 追跡外のため一覧に含まれません。いずれもリポジトリには同梱されず、各自で用意するものです。

  • models/ のGGUFモデル本体（.gitignore が models/ と *.gguf を除外。配置用の PLACE_MODELS_HERE.txt だけは公開対象として明示管理）
  • Whisperモデル（初回起動時に自動ダウンロード）
  • .venv/（Python実行環境）
  • chat_logs/（会話履歴。個人データ）
  • chat_settings.json（実行時設定。.example のみ追跡対象）
  • .git/ / __pycache__/ / .pytest_cache/
  • docs/（.gitignore がディレクトリ丸ごと除外）
  • ローカル環境固有の運用メモと起動スクリプト、過去バージョンのソース

この一覧自身について

この一覧ファイル自身は検証対象67件に含まれません。 自分のSHA-256を自分の中に書くと自己参照になり、内容を更新するたびに記載値と実際の値がずれて確定できないためです。

この一覧ファイルもGit管理対象であり公開されますが、ハッシュ検証の対象からのみ除外します。検証スクリプト（§4-1）も同じ除外を行うため、Git管理対象が68件になっても検証対象は67件で安定します。

2. 一覧全体の指紋

個別の67件を1つの値で代表させたものです。

MANIFEST_FINGERPRINT = a956e4fed056e0cf9de5d27b2cc0a3a28c30a8f564d63f068e64561e37f8b1f3

定義（再現に必要なため厳密に記します）:

  1. 対象は git ls-files の一覧に未追跡の新規公開予定4ファイルを加え、削除済みファイルを除いたうえで、この一覧ファイル自身を除外した67件
  2. パス文字列（/ 区切り、UTF-8）で昇順ソート
  3. 各行を <sha256小文字16進> + 半角スペース2個 + <相対パス> の形式にする
  4. 行区切りは LF、最終行にも LF を付ける
  5. 全体を UTF-8 でエンコードして SHA-256 を取る

行区切りを CRLF にしたりソート順を変えると別の値になるため、照合時はこの定義に従ってください。

4. 検証方法

4-1. 一括検証

リポジトリのルートで次のスクリプトを実行してください。日本語ファイル名を含むGit管理対象全件で動作を確認済みです。

# -*- coding: utf-8 -*-
"""Git管理対象予定ファイルのSHA-256を算出する。リポジトリのルートで実行する。

この一覧ファイル自身は自己参照になるため対象から除外する。
"""
import hashlib, os, subprocess

SELF = "SHA256.md"
PENDING_NEW = {
    "attachment_store.py",
    "prompt_inputs.py",
    "tests/test_attachment_store.py",
    "tests/test_prompt_inputs.py",
    "TERMS_OF_USE.md",
    "PRIVACY_POLICY.md",
    "DISCLAIMER.md",
    "THIRD_PARTY_LICENSES.md",
}

def sha256_of(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(1024 * 1024), b""):
            h.update(chunk)
    return h.hexdigest()

raw = subprocess.run(["git", "ls-files", "-z"],
                     capture_output=True, check=True).stdout
tracked = {
    p.decode("utf-8") for p in raw.split(b"\x00") if p
}
RENAMES = {
    "LLMローカル対話型AI.bat": "LLM_Local_chat_run.bat",
    "コード解説_やさしい版.md": "code_reference.md",
    "公開リポジトリ_SHA256一覧.md": "SHA256.md",
    "models/ここにモデルを追加してください.txt": "models/PLACE_MODELS_HERE.txt",
}
tracked = {RENAMES.get(p, p) for p in tracked}
# commit/stageを行わないv1.8.2作業中も、新規公開予定ファイルを検証する。
tracked.update(p for p in PENDING_NEW if os.path.isfile(p))
tracked = sorted(p for p in tracked if os.path.isfile(p.replace("/", os.sep)))
targets = [r for r in tracked if r != SELF]

lines = []
for rel in targets:
    local = rel.replace("/", os.sep)
    if os.path.isfile(local):
        lines.append(f"{sha256_of(local)}  {rel}")

manifest = "\n".join(lines) + "\n"
print(f"Git管理対象予定: {len(tracked)} 件")
print(f"検証対象:     {len(lines)} 件")
print("指紋: " + hashlib.sha256(manifest.encode("utf-8")).hexdigest())

PYTHONIOENCODING=utf-8 を付けると出力の文字化けを避けられます。

期待値: Git管理対象予定 68 件、検証対象 67 件、指紋 a956e4fed056e0cf9de5d27b2cc0a3a28c30a8f564d63f068e64561e37f8b1f3

指紋は検証対象67件のSHA-256だけから生成するため、この一覧ファイルを編集しても指紋は変わりません。 変わるのは67件のいずれかを変更した場合だけです。

4-2. 個別ファイルの確認

1ファイルだけ確認する場合は PowerShell の標準コマンドで足ります。

Get-FileHash -LiteralPath .\README.md -Algorithm SHA256

4-3. ⚠️ 使ってはいけない方法

git ls-files の出力を PowerShell のパイプラインへ流して Get-FileHash にかける形は使わないでください。

# ❌ 誤った結果を出す
git ls-files | ForEach-Object { (Get-FileHash -LiteralPath $_ -Algorithm SHA256).Hash }

現在の公開対象のモデル配置用ファイル名はASCIIです。ただし、この一覧は未追跡の公開予定ファイルも明示的に加え、自己参照を除外する必要があります。単純なパイプラインではその対象定義を再現できないため、4-1 の手順を使ってください。

5. この一覧が無効になる条件

以下のいずれかが起きた時点で、一覧は現状と一致しなくなります。

  • 検証対象67件のいずれかを編集した（1文字でも変わればハッシュは変わる）
  • 検証対象を追加・削除・改名した（件数と指紋が変わる）
  • 改行コードが変換された（.gitattributes により CRLF↔︎LF 変換が発生し得る）

この一覧ファイル自身の編集は、検証対象から除外しているため指紋に影響しません。

改行コードについての注意: LLM_Local_Chat.py はワーキングツリー上 CRLF で、git はコミット時に LF へ変換する旨の警告を出します。したがってこの一覧の値はワーキングツリー上のバイト列に対するもので、git オブジェクトのハッシュとは一致しません。GitHub からダウンロードした際、改行コードの差でハッシュが一致しないことがあります。
