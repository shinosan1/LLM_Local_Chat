スレッド 設計

🖥 メインスレッド
Tkinter mainloop
UI 描画・イベント処理。root.after(0, cb) 経由でのみ UI 更新を受け付ける
🤖 LLM ワーカー
都度生成・デーモン
ストリーミング推論ループ。完了時 root.after(0, _on_llm_done)
🔊 TTSWorker
常駐デーモン
発話キューをポーリング。発話開始／終了時 root.after(0, on_start/on_stop)
🎤 VoiceRecognizer
常駐デーモン
VAD → Whisper ループ。テキスト確定時 root.after(0, _voice_input)
🌐 API ワーカー
都度生成・デーモン
Kakeibo / Biolog への POST。完了時 root.after(0, _chat_write)

⚠ Tkinter を直接操作できるのはメインスレッドのみ

外部 API 連携

💴 Kakeibo（家計簿）モード
  • ポート: 8767
  • プロンプト注入: _kakeibo_build_prompt() で支出カテゴリ一覧とスキーマを挿入
  • JSON 抽出: _extract_kakeibo_json() で ```json ... ``` ブロックを正規表現でパース
  • 送信: POST /api/kakeibo/record をデーモンスレッドで非同期 POST
  • 必須フィールド: amount / category / store / date / type
❤ Biolog（健康記録）モード
  • ポート: 8766
  • プロンプト注入: _health_build_prompt() で体重・体脂肪・食事・活動スキーマを挿入
  • JSON 抽出: _extract_health_json() で計測値を取得
  • 送信タイミング: TTS 開始直後に非同期送信（VAD 排他を損なわない）
  • DB: SQLite（WAL 禁止・NTFS 非互換）

VRAM セーフティフィルタ

📊
ResourceMonitor
バックグラウンドで GPU 使用率を監視。
Whisper の δgpu% も考慮した動的 max_tokens 算出。
🛡
VRAMGuard
LLM ロード前に VRAM 残量を確認。
adjust_llm() で gpu_layers を自動削減。
不足なら CPU フォールバック。
⚡
adjust_inference()
推論直前に再チェック。
高負荷時は max_tokens を削減して実行。
閾値超過なら実行拒否 → エラーメッセージ表示。

まとめ

  • UI → Controller → Services の明確な3層分離
  • root.after() によるスレッド安全な UI 更新を徹底
  • _tts_active フラグ で TTS ↔ マイクの排他制御
  • VRAMGuard で GPU リソースを保護しつつ動的に最適化
  • Kakeibo / Biolog の API 連携をモードとして UI に統合
  • セッション要約 でコンテキスト長を効率的に管理
  • Windows 専用（SAPI5 TTS）だが、TTS 層は差し替え可能な構造
